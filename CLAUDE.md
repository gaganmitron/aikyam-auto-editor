## 0. What the product is (one paragraph)
A Python pipeline that turns long temple recordings into short vertical (9:16) Reels with **no human editing at run time**: analyse the footage (scenes, vision, sound) → pick candidate moments → plan a story (opening → buildup → ritual → reveal → climax → closing) → mix audio → render with FFmpeg → check its own result (QC) and re-edit. The user's goal: make it "much more intelligent", so reels look like advanced human editing. Private project (never sold or hosted for others). Remote: `github.com/gaganmitron/aikyam-auto-editor` (user: gaganmitron).

## 5. How it works (short; details in HANDOFF §4 and the code)
Entry: `aikyam-video process INPUT... -o results/NAME [flags]` (`aikyam_video/cli.py` → `pipeline.py` / `multi.py` → `stages.py`). Several inputs = ONE reel (assets v1, v2…).
1. **Analysis** (`stages.py`, cached per asset in `results/NAME/assets/vN/`, keyed by path+size+mtime): scenes (`scenes.py`, PySceneDetect; TransNetV2 in `.venv-beat` for cut points), vision per scene (`vision.py`: SigLIP zero-shot ~30 labels, embedding, aesthetic + no_text antonym scores, 10 story *beats* from `beats.py`), sound events (`audio.py`: CLAP), transcript (faster-whisper; skipped with `--no-transcript`).
2. **Moments** (`highlights.py`, `scoring.py`): candidates → validation (length, duplicates, black frames, `graphic_or_text_overlay` guard) → 7-part weighted score.
3. **Story** (`creative/`): `shots.py` measures every 0.5 s slot (sharpness, jitter, motion, luma, contrast, blown-out) and picks the best window inside a shot, never including *dead* slots (blocked lens, whip); `roles.py` + `data/roles.json` give each shot an affinity per role (labels, beats 25%, brightness for openings); `story.py` beam-searches the arc, penalises repeated beats/duplicates, tops up short reels, resolves overlaps, snaps edges to cuts; `transitions.py`, `pacing.py` (contemplative / devotional / festive profiles).
4. **Frame + colour** (`layout.py`, `reframe.py`, `grade.py`): tracked subject window ≤ 60% of the width over a blurred fill; clips colour-matched.
5. **Audio** (`mixer.py`, `bed.py`, `music*.py`): `--source-audio keep|off|bed`. `bed` = the recording's own most music-like stretch (picked across ALL inputs) as one continuous soundtrack. −16 LUFS, ducking, limiter.
6. **Render** (`render.py`, FFmpeg) → reel 9:16, square, landscape. **QC** (`creative/qc.py`) measures the encoded file and triggers a deterministic re-edit (`replan.py`).
Flags worth knowing: `--source-audio bed --no-transcript --no-captions` (what recent runs used), `--opening establish`, `--no-beats`, `--no-color-match`, `--experimental-selection` (aesthetic + coverage, opt-in), `--music-web`, `--music-file`, `--vision-model`.

### What the model currently looks for most in a video
Per moment score (weights in `scoring.py`): visual importance 25% (faces, lamps, sharp/well exposed), devotional relevance 20% (label weights: deity/aarti/abhishekam 1.0, idol 0.9, procession/sanctum view 0.8, priest/lamps/ritual hands 0.7, offerings/flowers/devotees/food 0.5, architecture/crowd/decorations 0.4), audio 15% (bell/conch/chant/bhajan; **zeroed in `off`/`bed` mode**), meaning 15% (transcript; **zero with `--no-transcript`**), novelty 10%, completeness 10%, position 5%. So in the recent silent runs it is mostly: *visually clean + devotional-looking + not repetitive*. Then each shot is fitted to a role: OPENING wants a wide, calm, bright "establishing" view; BUILDUP devotees moving toward the temple, rising energy; RITUAL aarti/abhishekam/ritual hands/offerings with energy; REVEAL a deity/idol/sanctum close-up, calm; CLIMAX procession/ritual at peak energy and sound; CLOSING calm, late, wide or devotional. Across the 127 clips in the 19 stored reels the top labels were aarti 26, devotees 23, idol 18, devotees_walking 15, procession 13, priest 7; beats (only 52 clips have one): approach 15, establishing 7, ritual_action 6, music 5, detail 5, procession 5, offering 4, community 3, darshan 2 — i.e. it rarely finds a true darshan/deity moment (the sources seldom contain one: inner sanctum is not filmed) and favours people arriving, wide views, rituals. Caveat: several reels are repeats on the same video.

## 8. Gotchas that cost time
- Shell: `pgrep -f`/`pkill -f` patterns that appear in your own command line kill your own shell. Use PIDs or anchored patterns. Do not chain `sleep`; wait on a PID or use the harness's background/monitor feature.
- `/tmp` was a small tmpfs: point pytest `--basetemp` and pip `TMPDIR` at a real disk.
- ffmpeg: `colorbalance` stops working after `eq`; use `colorchannelmixer`. `boxblur` fill bands are intentional.
- Analysis cache is keyed by file path + size + mtime; replacing a file re-analyses only that asset (asset ids are positional: v1, v2…). To reuse three cached assets in a new output folder, copy `results/OLD/assets/vN` and delete the changed one.
- The user's Wikipedia/YouTube fetches can be rate-limited (429); use `WebFetch` on file pages or wait.
- `--music-web` used to pollute the committed `music/library.json`; web tracks now go to the untracked `music/web/library.json`.
- QC metrics can be wrong: two of the most common warnings were artefacts (EXP-020). When QC flags something, look at the frames before "fixing" it.
- `realesrgan`/`basicsr` (pip) break on current torchvision: `basicsr.data.degradations` imports the removed `torchvision.transforms.functional_tensor`. Community fix: write a one-line shim file `<venv>/lib/python3.9/site-packages/torchvision/transforms/functional_tensor.py` containing `from torchvision.transforms.functional import rgb_to_grayscale`. Not a repo file -- redo it in any fresh venv (EXP-032).
- **`pip install mediapipe` silently replaces `opencv-python-headless` with `opencv-contrib-python` 5.x, which broke `cv2.CascadeClassifier` everywhere in this codebase** (face detection: `shots.py`, `vision.py`, `reframe.py`, `qc.py`). Fix: `pip uninstall opencv-contrib-python opencv-python && pip install --force-reinstall opencv-python-headless==4.10.0.84` (the pin in `pyproject.toml`) right after installing mediapipe/realesrgan/any package that pulls in a different opencv build; re-run the affected tests to confirm.
- mediapipe >= 1.0 dropped the old `mp.solutions.*` API; use `mediapipe.tasks.python.vision` (Tasks API) and download the `.tflite` model file yourself (e.g. `blaze_face_short_range.tflite` from `storage.googleapis.com/mediapipe-models/...`) -- it is not bundled in the pip package the way older docs describe (EXP-031).
