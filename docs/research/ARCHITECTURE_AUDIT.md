# Architecture audit: what Aikyam already has, mapped onto the brief's vNext stages (2026-09-26)

Brief §28 steps 1–3 ("inventory the repository, map modules to stages, identify existing implementations before adding files"). Source of truth is the code as of commit `ef7d749` plus the uncommitted docs. Function names below were read from the files, not from memory.

**Amendment that applies here (user decision, 2026-09-26):** recorded audio of the input videos is never used in a reel (own music only). So Whisper/speech, CLAP events on the source audio and the source's loudness are *not* editorial observations for the vNext design. The code still computes them (`--source-audio keep` default; `off`/`bed` zero their weights but do not skip the analysis): whether `off` becomes the default and skips that analysis is an open question to the user.

## 2. What the brief lists as "do not rebuild" — confirmed present
FFmpeg rendering, Creative Engine, Ken Burns (stills), music alignment, crossfades, captions, chunking, Whisper, PySceneDetect, SigLIP, CLAP, story planner, experiment logging, QC, audio cleaning, variants: all exist. **Nothing on that list needs to be rebuilt.**

## 3. The real gaps (in the brief's P0 order)
1. **Observation schema/versioning** (P0.2): small — version + provenance on the existing cache files; add per-slot observations only when a feature needs them.
2. **Candidate representation** (P0.3): add to `Shot`: `shot_size`, `angle`, `camera_motion`, `quality_model` score; nothing else yet.
3. **Event construction** (P0.4): wire `events.event_windows` into candidate generation behind a flag; measure against the current pool (EXP-004 shows the signal is real).
4. **Editorial state + sequence scoring** (P0.5–P0.6): extend the beam state with previous size / energy / motion / brightness and add transition costs (see `SEQUENCE_SEARCH.md`).
5. **Top-K sequences + deterministic critic before render** (P0.7): return the top-K beam members, score them with a pre-render critic; keep `autoedit` variants for opening/pacing.
6. **Decision trace with WHY_REJECTED** (brief §4): record the per-term breakdown and the rejected top candidates.
7. **Creative Engine reuse** (P0.8): already true.

## 4. Things the audit found that the brief did not know
- The beam already produces the candidate sequences the brief wants; they are discarded (`story.py`: `ok[0]`).
- `transitions.plan_transitions` runs after the sequence is fixed, so a bad transition can never make the search prefer another order.
- `autoedit.reel_score` is a weighted sum of measured properties, not a learned taste model, and it says so; a preference model (`SEQUENCE_SEARCH.md` §5) would be new.
- The one known-red test (`test_story_follows_the_arc…`) sits on exactly this code (role assignment in a deliberately thin pool); read EXP-002b/003 before changing the beam.
- No code path uses a GPU except Whisper (`transcribe.py`): see `HARDWARE_BUDGET.md`.
